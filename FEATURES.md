## P1 Control Plane (server ↔ daemon) — Verified end-to-end
- [x] WS `/daemon/connect?key=` TS implementation + machine registration/heartbeat persistence + push to frontend (one-shot machine ready is buffered across async authentication)
- [x] Message protocol: agent:start/deliver + ready/status/activity/trajectory/session (daemon↔server fully wired)
- [x] `--resume` wake-up supported; machine online status persisted
- [x] **Single-turn cold-start wake**: deliveries queued while an agent starts are consumed by the existing STARTUP/RESUME inbox-check nudge instead of being flushed as a second notice, so one message cannot drive duplicate replies after a cold wake; already-running agents keep the 3 s batched delivery path
- [x] **Reconnect robustness + per-machine key rotation**: an unknown/removed `sk_machine_*` key is rejected with WS close `4001`, so the daemon backs off to the 30s cap with an actionable error instead of reconnect-storming (backoff resets only after the server accepts the connection). `POST /api/servers/:id/machines/:id/reconnect` rotates the key on the **same** machine row; a **Reconnect** button on offline machines lets a lost-key machine rejoin without a duplicate row
- [x] **Reconnect catch-up + offline reachability**: on machine reconnect the server wakes only agents with a *wakeable* backlog (`reconnectCatchup.ts`; criterion mirrors `createMessage` — DM/@ always, ambient only with `inbox:receive`), so missed messages get processed without waking idle agents (no token burn). The Composer shows an offline-reachability hint for the agents a message will reach, and a global toast (`toast.tsx`) surfaces start/restart 503s and create-while-offline
- [x] **Idle-sleep**: agent auto-kills process when idle (`OPEN_TAG_IDLE_MS`, default 10 min), resumes on next wake; agent:stop/sleep linked
- [x] **Dynamic memory pressure system**: no per-agent limits until free memory drops below `OPEN_TAG_PRESSURE_MEM_MB` (default 500 MB); under pressure new agents queue and running agents are capped at current RSS + a fair-share margin (Windows Job Object / Linux cgroup)

Attempt-fenced fan-out, the `delivery-admission-v2` two-phase admission barrier, per-agent FIFO, and bounded causal depth/budget/pair dedupe prevent stale dispatch, duplicate public replies, and unbounded agent loops. Full model: `ARCHITECTURE.md` §II–IV + `docs/exec-plans/completed/conversation-turns.md`
